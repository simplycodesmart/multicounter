# Contributing to MultiCounter

Thank you for your interest in contributing to MultiCounter! Contributions, suggestions, bug reports, and improvements are welcome.

Please read these guidelines before submitting a contribution.

## 1. Before You Contribute

- Read the project's `LICENSE.txt`.
- Check existing issues and pull requests to avoid duplicate work.
- For major changes, open an issue first to discuss the proposed implementation.
- Keep contributions focused on improving MultiCounter.

## 2. Types of Contributions

We welcome contributions in the following areas:

- Bug fixes and performance improvements.
- UI/UX improvements.
- New counter features and customization options.
- Android widget improvements.
- Accessibility enhancements.
- Documentation and code quality improvements.
- Automated tests and compatibility improvements.

## 3. Development Setup

Requirements:

- Flutter SDK
- Dart SDK
- Android Studio or VS Code
- Git

Clone the repository:

```bash
git clone <YOUR_REPOSITORY_URL>
cd multicounter
```

Install dependencies:

```bash
flutter pub get
```

Run the application:

```bash
flutter run
```

Run tests:

```bash
flutter test
```

Check code formatting:

```bash
dart format .
```

Analyze the project:

```bash
flutter analyze
```

## 4. Coding Guidelines

Please follow these standards:

- Follow official Dart and Flutter conventions.
- Use clear and meaningful variable and function names.
- Keep widgets and services modular and reusable.
- Avoid unnecessary dependencies.
- Handle errors gracefully.
- Add comments where implementation logic is not obvious.
- Maintain compatibility with existing features.
- Do not introduce breaking changes without discussion.

## 5. Branching Guidelines

Create a separate branch for each contribution.

Suggested naming conventions:

- `feature/add-new-counter`
- `fix/widget-refresh-issue`
- `ui/improve-widget-design`
- `docs/update-readme`

Avoid submitting unrelated changes in the same pull request.

## 6. Commit Message Guidelines

Use descriptive commit messages.

Examples:

```text
feat: add customizable counter colors
fix: resolve Android widget refresh issue
ui: improve counter card layout
docs: update installation instructions
test: add counter calculation tests
```

## 7. Pull Request Process

Before submitting a pull request:

1. Ensure your changes are focused and complete.
2. Run `dart format .`.
3. Run `flutter analyze`.
4. Run `flutter test`.
5. Test affected functionality where possible.
6. Update documentation if necessary.
7. Provide a clear description of your changes.

Your pull request should include:

- Summary of changes.
- Reason for the changes.
- Screenshots or recordings for UI changes.
- Testing performed.
- Related issue number, if applicable.

## 8. Bug Reports

When reporting a bug, include:

- A clear description of the problem.
- Steps to reproduce it.
- Expected behaviour.
- Actual behaviour.
- Flutter and Dart versions.
- Device and operating system details.
- Screenshots or logs, if available.

## 9. Feature Requests

For feature requests, explain:

- What feature you want.
- Why it would be useful.
- How you expect it to work.
- Screenshots or examples, if relevant.

## 11. Code of Conduct

Be respectful and constructive.

- Treat everyone with respect.
- Welcome different perspectives.
- Provide constructive feedback.
- Avoid harassment, discrimination, and personal attacks.
- Focus discussions on improving the project.

Unacceptable behaviour may result in contributions being rejected.
